# 官网实测数据

本页是其他文档引用的**原始数据**。所有数值来自 2026-10-08 在浏览器中读取 [终末地官网](https://endfield.hypergryph.com/) 的计算样式与样式表规则；没有转存官方的样式文件、图片或字体。

本页只记官网首页（单页长滚动的那一份）。同一域名下的 [云游戏页](../surfaces/cloud.md)（`/cloud`）是另一套构建，样式表、根字号、字体、黄色都和首页不同，数据另见 [measurements-cloud.md](measurements-cloud.md)。

- 测量视口：横屏 1024×768 与 1440×810，竖屏 375×812。
- 2026-10-12 在 1440×810 下对着官网抽查过一遍：根字号的换算、字族、颜色、各控件的尺寸与状态色、阴影、关键帧、八个版块的顺序都没有变。同时补上了当时没有记的几样——各控件的圆角（第 4、8 节）、导航轨的当前项与图标宽度（8.1）、2D / 3D 切换器（8.14）——并改正了一处：分页条两端的是圆钮，不是方钮（8.6）。
- 2026-10-14 复查了语言下拉（8.12）：补上顶边条的位置和圆角，并记下这个下拉现在已经不渲染、只剩样式表里的规则。
- 2026-10-14 重量了加载页（8.13）：原来只记了色值和字号，这次把排法、横竖两套位置和退场的时间线补全了；动效一节跟着更正了一处。
- 2026-10-24 量云游戏页时顺带核对了账号 SDK：更正了 3.4 的品牌色，第 5 节末尾补上 SDK 阴影实际生效的值。
- 官网会随版本更新改版。数值过期时以重新测量为准，并更新本页日期。
- 样式表里的类名带构建哈希（如 `Button_button__njqVS`），下文统一去掉哈希，只保留组件名。

## 1. 尺寸基准

官网全站用视口比例缩放的 `rem`：

| 方向 | `html` 字号 | 换算 |
| --- | --- | --- |
| 横屏 | `100vw / 160` | 设计稿 1920px 宽时 `1rem = 12px` |
| 竖屏 | `100vw / 67.5` | 设计稿 1080px 宽时 `1rem = 16px` |

验证：1024px 宽时 `html` 字号为 6.4px，1440px 宽时为 9px，375px 宽竖屏时为 5.556px。

下文的 `rem` 都是这种"流式 rem"，括号里的像素值按 1920px 设计稿换算。

账号 SDK 的样式里有一处带偏移的阴影，不属于站点本身（见 3.4）。

2026-10-24 补：弹层上带偏移的是皮肤规则里的 `0 E(9.6) E(19.2) rgba(0,0,0,.25)`（`E(n)` 是按 SDK 自己的字号基准折算的长度，1440 宽时 E(n) = 0.8n px）。它的选择器要求皮肤类挂在祖先上，SDK 却把皮肤类挂在每一层自己身上，所以实际匹配不到；弹层真正生效的是零偏移的 `0 0 E(24) rgba(0,0,0,.5)`（1440 宽时 19.2px）。见 [云游戏页实测](measurements-cloud.md) 11.4。

2026-10-14 更正：自定义的 `cubic-bezier` 有一条，上面的统计只数了过渡、漏了动画——加载页退场时铺满整屏的那一层用的是 `cubic-bezier(1, 0, 0.7, 1)`（8.13）。

关键帧：

| 名称 | 内容 |
| --- | --- |
| `flashing` | `opacity`：0 → .5（10%）→ 0（11%）→ .5（20%）→ 0（21%）→ .5（40%）→ 0（41%）→ 1（100%），三次短促闪烁后点亮 |

| `rotate` | 匀速旋转一周 |
| `fadeIn`（加载页） | `scaleX(0)` → `scaleX(1)`。用在退场时铺满整屏的那一层上：0.6s、延迟 0.5s，见 8.13 |

2026-10-14 重量。这一页只在首次载入时出现一两秒，所以除了读样式表里 `00-Loading` 模块的规则，还在同源的内嵌页里把一次完整的加载逐帧记了下来。2026-10-08 那次只读了色值和字号，没有看排法——当时记的"进度条入场 `scaleX(0)` → `scaleX(1)`"其实是退场时铺满整屏的那一层，不是进度条。

动效（时间从"全部资源就绪"那一刻起算）：

| 阶段 | 内容 |
| --- | --- |
| 充填 | 进度每变一次，条长、读数基线的位置、底图的模糊各补间 0.5s；读数的数字就是补间中的位置取整。逐帧看是开头快、收尾慢；补间是脚本做的，样式表里读不到它的缓动 |
